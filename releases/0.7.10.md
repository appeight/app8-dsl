Patch release on 0.7.9. All SDKs move to 0.7.10 together (iOS, Android, web renderer). `DSL_VERSION` stays 1.1.

- Engines never crash on unexpected input ([index.md](../docs/index.md#unknown-and-mistyped-values)): unknown or mistyped values are ignored, never fatal. A value of the wrong type takes the property's default, as if it were absent, and its siblings, its component and the screen stay; an unknown enum value takes the default; an unknown component type or a template that does not exist is skipped; out-of-range numbers (huge sizes or indexes, negative insets, `NaN` from an expression, layout constants or multipliers beyond 1e7 pt) are clamped or ignored. Each ignored value logs one `value.ignored` warning with its JSON path (Android's `decode.dropped` is renamed `value.ignored`). A component that fails to build renders nothing in apps and share pages. On iOS, `App8.showErrors` (on in debug builds, off in release builds) draws it as a red box instead, and preview hosts may turn it on; the web renderer's `AppRuntime({ showErrors })` outlines it in editor previews. Before, iOS and the web renderer rejected a screen with a mistyped value on its own fields (iOS showed its error screen), and some inputs crashed the iOS or Android engine (unregistered collection template ids, huge counts and spans, non-finite numbers, inverted ranges).
- Android: an action with one mistyped field now stays in its list with that field dropped (its default applies). Before, the whole action was dropped.
- Minimum engine version ([host-integration.md](../docs/host-integration.md#minimum-engine-version), `app.minEngineVersion`): an app can name the oldest engine release that renders it correctly. The engine does not check it; the host compares it with `EngineVersion` before it starts the engine and shows its own screen (for example, asking the user to update) when the installed engine is older.
- Android: `App8DataSource.persistenceId` names the storage of an app's persisted variables and photos, ahead of `app.id`, `bundleId` and `title`, as on iOS since 0.7.9. Set it when one host opens several apps, so their saved values stay apart. Default `null`: apps keep their storage.
- Screen light and dark ([screen.md](../docs/components/screen.md#light-and-dark), `screen.content.userInterfaceStyle`: `"light"` or `"dark"`): one screen in its own appearance, whatever the app's, like iOS `overrideUserInterfaceStyle` on the screen's view controller. While the screen is shown, its `{light, dark}` colors, system colors and default background, its navigation bar (title, bar buttons and their iOS 26 glass, the back button, the search field; on Android the top app bar), the status bar (and Android's system bar icons), and alerts, sheets and modals presented from it use that style. Other screens are not affected: pushing a dark screen in a light app switches the bar to dark with the push, popping switches it back. Absent, the screen follows the app (`userInterfaceStyle`, then `defaultUserInterfaceStyle`, then the system). Engines up to 0.7.9 ignore the field. On iOS, Android and the web renderer (iOS and Android modes).
