Patch release on 0.7.14. All SDKs move to 0.7.15 together (iOS, Android, web renderer). `DSL_VERSION` stays 1.1. No new keys. Two iOS fixes to the 0.7.14 behaviours.

- Stretchy top, iOS ([scroll-view.md](../docs/components/scroll-view.md#stretchy-top)): a hero's child pinned to the safe area's top (a watermark, a number under the status bar) keeps its place on screen during a pull, like one pinned to the hero's top. In 0.7.14 it rode up by the pull: inside a scroll view the hero's content view got the hero's own safe-area inset, which shrinks as the hero moves down with the pull. The web renderer already behaved this way.
- Zoom, iOS ([transitions.md](../docs/transitions.md)): only chrome outside the aligned element's scroll view (or outside its own container when there is none) counts as the zoomed screen's floating controls. In 0.7.14 content next to the photo in the same cover, such as a gradient and a name on a profile cover, was taken for controls: it was missing while the zoom ran and stayed fixed above the screen during an interactive pop. It now zooms with the screen. A photo viewer's close button and page counter still keep their size and fade.
