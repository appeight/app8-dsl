Unreleased. Minor release of the iOS + Android train. Host-provided views and feature packages.
- `native` component: embeds a view the host app registers under a module name (`properties.module`), with `props` (expressions, re-resolved when variables change), `actions` keyed by the module's event names with the payload in scope as `event`, and a DSL `fallback` shown when the host has no such module (no fallback: an empty view and a `native.module.missing` warning). Every module event is also posted on the event bus as `native.<module>.<event>`. iOS: `App8.registerNativeComponent(_:factory:)` with `App8NativeContext`. Android: `App8Config(nativeComponents:)` (planned; renders the fallback until then). Studio: `registerNativeComponent` in the web renderer.
- Prefabs: versioned feature packages (screens, templates, styles, app variables, params) instantiated in `app.json` `prefabs` and expanded by the bundle builder into ordinary screens with ids prefixed `<instanceId>_`. Params use `{ "$param": … }`, `{ "$spread": … }` and `${param.…}` / `${instance}` / `${id.…}` in strings. SDKs see only the expanded bundle.
- iOS: `emit` payloads and `openURL` urls in collection `onItemTap` actions now resolve against the tapped item (`{{item.sku}}`).
