Unreleased. Minor release of the iOS + Android train. Host-provided views, feature packages, and the DSL pieces a feature package needs (control flow, HTTP, more array and date tools).
- `native` component: embeds a view the host app registers under a module name (`properties.module`), with `props` (expressions, re-resolved when variables change), `actions` keyed by the module's event names with the payload in scope as `event`, and a DSL `fallback` shown when the host has no such module (no fallback: an empty view and a `native.module.missing` warning). Every module event is also posted on the event bus as `native.<module>.<event>`, and `analytics` bindings keyed by event name fire for it. iOS: `App8.registerNativeComponent(_:factory:)` with `App8NativeContext`. Android: `App8Config(nativeComponents = …)` with `App8NativeComponent` and `App8NativeContext`. Studio: `registerNativeComponent` in the web renderer.
- Prefabs: versioned feature packages (screens, templates, styles, app variables, params) instantiated in `app.json` `prefabs` and expanded by the bundle builder into ordinary screens with ids prefixed `<instanceId>_`. Params use `{ "$param": … }`, `{ "$spread": … }` and `${param.…}` / `${instance}` / `${id.…}` in strings. SDKs see only the expanded bundle.
- iOS: `emit` payloads and `openURL` urls in collection `onItemTap` actions now resolve against the tapped item (`{{item.sku}}`).
- Actions `forEach` (`items`, `as`, `index`) and `with` (`values`): run nested actions with bound, read-only names. `with` lets one reusable action list (a prefab param) take different inputs per call site.
- Array actions `insertArrayItem` (`index`, negative from the end), `upsertArrayItem` (`matchBy`, replace or add at `position`) and `removeArrayItem` (`matchBy` + `value`, or `index`). `incrementArrayItem` with a `null` or missing match key does nothing on every platform.
- `request` action: HTTP `GET`/`POST`/`PUT`/`PATCH`/`DELETE` with JSON `body`, `headers`, `resultVariable`, `onSuccess` / `onError` and `response` (`status`, `body`, `headers`) in scope; 30 s timeout; asynchronous (callbacks need the starting screen alive; an app-scope `resultVariable` is always written). Hosts authorize, route or reject requests in `prepareRequest` (iOS and Android `App8DataSource`, web `AppRuntime`).
- `reloadDatasource` action refetches a datasource and updates every app and live-screen variable bound to it, then runs optional `onSuccess` (or `onError` on failure). App variables accept `source` (loaded at app start; with `persist`, the stored value shows until the source loads).
- A `navigation` after `dismiss` in one action list waits for the dismissal, then runs from the presenting screen's navigation stack.
- Expressions: array literals evaluate every element (`[event.item, 1, name + '!']`); new `prepend`, `append`, `uniqueBy`, `remove`; dates `now()`, `today()`, `addDays`, `addHours`, `startOfDay`, and every date function accepts `Z` and numeric offsets (`+00:00`).
- Every color-valued style field accepts an expression returning a hex color, re-evaluated when its variables change.
- `properties.isHidden` hides every component type; a hidden stack child takes no space.
- A vertical or grid collection that does not scroll itself (`layout.scrollEnabled: false`, or inside a vertical `scrollView` with no height of its own) sizes to its self-sized items.
