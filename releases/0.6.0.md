Minor release of the iOS + Android train: the DSL spec, both engines and both cloud SDKs move to 0.6.0 together. Host-provided views, feature packages, and the DSL pieces a feature package needs (control flow, HTTP, more array and date tools).

New
- `native` component: embeds a view the host app registers under a module name (`properties.module`), with `props` (expressions, re-resolved when variables change), `actions` keyed by the module's event names with the payload in scope as `event`, `analytics` bindings keyed by event name, and a DSL `fallback` shown when the host has no such module (no fallback: an empty view and a `native.module.missing` warning). Every module event is also posted on the event bus as `native.<module>.<event>`. iOS: `App8.registerNativeComponent(_:factory:)` with `App8NativeContext`. Android: `App8Config(nativeComponents = …)` with `App8NativeComponent` and `App8NativeContext`. Web renderer: `registerNativeComponent`.
- Prefabs: versioned feature packages (screens, templates, styles, app variables, params) instantiated in `app.json` `prefabs` and expanded by the bundle builder into ordinary screens with ids prefixed `<instanceId>_`. Params use `{ "$param": … }`, `{ "$spread": … }` and `${param.…}` / `${instance}` / `${id.…}` in strings. SDKs see only the expanded bundle.
- Actions `forEach` (`items`, `as`, `index`) and `with` (`values`): run nested actions with bound, read-only names. `with` lets one reusable action list (a prefab param) take different inputs per call site.
- Array actions `insertArrayItem` (`index`, negative from the end), `upsertArrayItem` (`matchBy`, replace or add at `position`) and `removeArrayItem` (`matchBy` + `value`, or `index`). A `null` or missing match key does nothing in every array action on every platform, `incrementArrayItem` included.
- `request` action: HTTP `GET`/`POST`/`PUT`/`PATCH`/`DELETE` with JSON `body`, `headers`, `resultVariable`, `onSuccess` / `onError` and `response` (`status`, `body`, `headers`) in scope; 30 s timeout; asynchronous (callbacks need the starting screen alive; an app-scope `resultVariable` is always written). Host hook `prepareRequest` authorizes, routes or rejects requests (iOS and Android `App8DataSource`, web `AppRuntime`).
- `reloadDatasource` action refetches a datasource and updates every app and live-screen variable bound to it, then runs optional `onSuccess` (or `onError` on failure). Host hook `App8DataSource.reloadDatasource(screenId, datasourceId)` (defaults to `getDatasource`) lets a caching data source fetch fresh data; both cloud SDKs implement it, so a reload no longer returns the copy cached with the screen.
- App-scope source: app variables accept `source` (loaded at app start without blocking the first screen; with `persist`, the stored value shows until the source loads).
- A `navigation` after `dismiss` in one action list waits for the dismissal, then runs from the presenting screen's navigation stack.
- Expressions: array literals evaluate every element (`[event.item, 1, name + '!']`); new `prepend`, `append`, `uniqueBy`, `remove`; dates `now()`, `today()`, `addDays`, `addHours`, `startOfDay`, and every date function accepts `Z` and numeric offsets (`+00:00`). Date functions return `null` for an input that does not parse (`formatDate`, `formatTime`, `timeAgo`, `ageInYears`, `daysBetween` and `daysUntil` used to return `""` or `0`).
- Color expressions everywhere: every color-valued field (component styles, control tints, page dots, collection and swipe-action backgrounds, shape and map route colors, label spans, navigation bar and tab bar colors) accepts an expression returning a hex color, re-evaluated when its variables change. A non-hex result leaves the field unset and logs `style.color.invalid`.
- `isHidden` everywhere: `properties.isHidden` (boolean or expression) hides every component type and follows component states; a hidden stack child takes no space.
- Self-sizing collections: a vertical or grid collection that does not scroll itself (`layout.scrollEnabled: false`, or inside a vertical `scrollView` or a collection cell with no height of its own) sizes to its self-sized items, and the enclosing cell grows with it.
- `incrementVariable` / `incrementArrayItem` `by` accepts an expression that gives a number.

Fixes
- Decoding follows the docs (found by the conformance suite): boolean and number properties take a literal as well as an expression (toggle `isOn` / `isEnabled`, slider `value`, pageControl `numberOfPages` / `currentPage`, activityIndicator and shimmer `isAnimating`, and others; a literal used to drop the component); a component without `id` gets a stable id from its position instead of being dropped (Android); `image` without `properties.type` infers it from `url` (remote) or `asset` (local); a bad action inside an action list reports its own path (`actions[1].type`).
- `variable` is accepted as an undocumented alias of `variableName` on every platform; `variableName` wins when both are present.
- iOS: `emit` payloads and `openURL` urls resolve against the action's scope, so `{{item.id}}` works in collection `onItemTap` actions.
- iOS: `pageControl` media-style dots take `pageIndicatorTintColor` and `currentPageIndicatorTintColor` again (hex or color expression); unset, the dots stay white.
- iOS: app variables are defined in dependency order, so a computed app variable that reads other app variables is no longer dropped.
- iOS: a navigation-bar button runs every action type (`showAlert`, `request`, `updateVariable`, …), not only `dismiss`, `navigation` and `completeFlow`.
- iOS: an `icon` `tintColor` property is no longer reset to the style tint when the style is applied again.
- Android: outline rings with square corners keep their hole on Android 12 and earlier (they drew as a solid fill).
- Android: self-sizing grid rows stretch every item to the row height.
- Android: action lists run without a main dispatcher on a host JVM (falling back to the calling thread), so unit tests that build an instance no longer fail with "Dispatchers.Main was accessed". On a device nothing changes.
