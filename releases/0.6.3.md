Patch release on 0.6.2: the DSL spec, both engines, both cloud SDKs and the web renderer move to 0.6.3 together. Two additions found while building the first native feature module and its screens, and iOS navigation bar fixes.

New
- Native component visibility. A `native` component knows when the user can see it: its screen is the topmost presented screen of the selected tab (not under a modal or sheet, not a background tab, not lower in a navigation stack), the app is in the foreground, and the component is on screen (in the window or composition, not `isHidden`, not an offscreen render or an off-screen collection cell). `true` arrives after the appear transition completes and `false` when a disappear transition starts, on the main thread, once per change; the fallback has a visibility too. iOS: `App8NativeContext.isVisible` and `onVisibilityChange`. Android: `App8NativeContext.isVisible`, a new context on each change. Web renderer: `NativeComponentProps.visible` (`live` stays as a deprecated alias). DSL: `appear` and `disappear` keys in the component's `actions` (and `analytics`), empty payload, not posted on the event bus; a module can no longer emit those two names (`native.event.reserved` warning). See [native.md — Visibility](../docs/components/native.md#visibility).
- `bottomBar` on screens: a component (usually a `stackView` of buttons) pinned at full width above the bottom safe area, or above the tab bar, with `insets` (default 12 top, 16 sides, 8 bottom). Its height is added to the screen's bottom safe area, so scroll content gets the matching inset. `style.background` `"system"` (default) gives the platform treatment: iOS 26 bottom scroll-edge effect (`edgeEffect` `soft` or `hard`), iOS 18 to 25 toolbar appearance, Android Material 3 surface that turns `surfaceContainer` when content scrolls under it; a `material` or `fill` style entity replaces it. `hidden` (boolean or expression) slides and fades the bar out and in over 0.33 s with a cubic ease-out. See [navigation.md — Bottom Bar](../docs/navigation.md#bottom-bar).

Fixes
- iOS 26+: an unset or `automatic` `navigationBar.topEdgeEffect` resolves to `soft` (the progressive blur of the system bars) instead of a hard band, and the bar tracks the screen's main vertical scroll view.
- iOS: a vertical scroll view with `contentInsetAdjustment: automatic` keeps a short page below the navigation bar.
- iOS: a navigation bar button's `navigation` action runs through the screen's action executor, so `presentation`, `detents`, `grabber`, `transition` and `params` expressions apply (a sheet opens as a sheet).
