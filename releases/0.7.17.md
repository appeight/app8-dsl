Patch release on 0.7.16. All SDKs move to 0.7.17 together (iOS, Android, web renderer). `DSL_VERSION` stays 1.1. No new keys: `style.alpha` now also takes an expression, and a `multiplier` on a position now applies on every platform; bundles that don't use them render as before. One more iOS fix for the scroll end.

- `alpha` expressions in `style` ([styles.md](../docs/styles.md#alpha-expressions)): every component style's `alpha` is a number or an expression, resolved in the component's scope and re-evaluated when its variables change. Before 0.7.17 iOS failed the style on an expression (the component lost its style, and a bottom bar's component failed its whole screen, which never opened) and Android drew it opaque; the web renderer already resolved it.
- Multipliers on positions ([layout.md](../docs/layout.md#multipliers-on-positions)): a `multiplier` on `leading`, `trailing`, `top`, `bottom`, `centerX` or `centerY` scales the target's position in the superview's bounds, as UIKit does: `centerX` × 2 of the superview is its trailing edge, so markers sit at fractions of a frame. Before 0.7.17 iOS and Android ignored it, and the web renderer also scaled the superview's own offset. A zero multiplier on a position is ignored.
- Unknown and mistyped values inside a bottom bar's component and a context-menu preview ([index.md](../docs/index.md#unknown-and-mistyped-values)) are now ignored with a `value.ignored` warning, like everywhere else. Before, one bad value there failed the screen on iOS and dropped the whole bar on Android.
- A screen that cannot be decoded is logged at error level with its id and JSON path, in release builds too (iOS system log, subsystem `dev.app8.engine`; Android logcat tag `App8`, `screen.load.failed`). Before, it failed silently unless debug logging was on.
- Bar buttons: no change. `action` is an Action or a list of actions run in order ([navigation.md](../docs/navigation.md#bar-action)), on every engine since 0.7.3.
- Scroll end, iOS ([scroll-view.md](../docs/components/scroll-view.md)): a wrapping label inside a hidden view no longer measures its wrap; it measures once shown. A hidden stack item still counts on its stack's cross axis on iOS, so chips duplicated across horizontal rows and hidden in all but one were measured at zero width (one word per line) and made their rows as tall as several lines; later re-measures changed the page height after a scroll had come to rest at its end and the content jumped (up to 113 pt on a report screen). Android and the web renderer leave hidden stack items out of layout and never showed it.
