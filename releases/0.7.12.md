Patch release on 0.7.11. All SDKs move to 0.7.12 together (iOS, Android, web renderer). `DSL_VERSION` stays 1.1. No new keys. Two spec texts now say what the engines do, and four engine fixes bring iOS, Android and the web renderer back in line.

- Scroll end (iOS): a wrapping label (`numberOfLines` 0) keeps its wrap when a variable update re-applies the same text. Before, every variable change re-measured every wrapping label, and for one layout pass each reported a single line. This includes variables the labels don't use, such as a screen timer or a scroll view's `outputVariable`. An enclosing scroll view's content was briefly short, so a scroll that came to rest in that pass stopped short of the end: the last rows stayed under the tab bar or bottom bar, and a pull showed them and then snapped back.
- Stack children ([layout.md](../docs/layout.md#constraints-in-uistackview-arranged-subviews)): a length along a stack's axis relative to the stack's own length is circular, because the stack is as long as its children. An example is `height >= superview + 36` in a vertical stack. Every engine now gives it a priority of 749 when it is `required`, so it yields to the arrangement and the children's content sizes. Before, iOS broke one of the stack's own constraints, and a collection card's text column drew over its photo. Android squeezed the next child to zero height. The web renderer already drew it this way.
- `lineHeight` `multiplier` ([styles.md](../docs/styles.md#lineheight-types)) multiplies the font's natural line height (UIKit `lineHeightMultiple`), not the font size. iOS and the web renderer always worked this way, and the spec text now says so. Android now uses a bundle font's own natural height; up to 0.7.11 it used SF Pro's 1.19 em for every font. To carry a CSS `line-height` over, divide it by the font's natural height, or use `fixed`.
- `shape.progress` in the wrapped `{ value, animation }` form ([animations.md](../docs/animations.md#per-property-animations)): the web renderer draws the fill and animates changes as iOS and Android do. Before, it drew only the track.
- Constraint targets ([layout.md](../docs/layout.md#targets)): a bare id (`"target": "photo"`) is documented as a compatibility shorthand for `sibling(photo)`, which every engine already accepted. Write `sibling(id)`. The web renderer's bundle lint warns on bare ids (`constraint.bareTarget`).
